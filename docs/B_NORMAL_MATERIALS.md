# B_NORMAL — фотографические материалы, этап 3

**Статус:** кандидат производства арта, не финальная сцена и не изменение рабочей игры.

В исходную 3D-сцену кухни добавлены **четыре фотосканированные CC0 текстуры** (цвет/albedo) от [Poly Haven](https://polyhaven.com/license):

- [Rusty Painted Metal](https://polyhaven.com/a/rusty_painted_metal) — следы краски и износа на шкафчиках, умеренно, чтобы стены не стали ржавыми.
- [Concrete Floor](https://polyhaven.com/a/concrete_floor) — микро-фактура пола, модульных панелей и эмали.
- [Wood Table](https://polyhaven.com/a/wood_table) — древесина стола и полок.
- [Metal Plate](https://polyhaven.com/a/metal_plate) — фотографическая микро-фактура металлического покрытия.

Текстуры сохраняются внутри **того же** GitHub-проекта в `art/materials/cc0/*.jpg`. Исходные URL, размеры и MD5 **зафиксированы** в `production/geometry/B_NORMAL/fetch_cc0_materials.py`. Непроверенный или изменившийся файл отвергается. При сборке GitHub Actions скачивает четыре материала, проверяет и сохраняет их в `main` вместе с единственным `art/candidates/B_B_NORMAL_360_geometry.webp`. Движок игры **не требует доступа к интернету**.

Детали рендера: фотоматериал проецируется по **локальным мировым координатам плоскостей коробок**, а не по пикселям экрана или всей панораме. Направления UV закреплены за физическими плоскостями, а снимки цветокорректируются в практические оттенки работающей станции. Это оставляет неизменными 97 объектов геометрии, положение раковины, зеркала, чайника, стола и семь тестируемых сюжетных UV-центров.

Воспроизводимость:
```bash
python -m pip install numpy pillow
python production/geometry/B_NORMAL/fetch_cc0_materials.py
python production/geometry/B_NORMAL/verify_kitchen.py
python production/geometry/B_NORMAL/render_kitchen360.py --width 2048 --out art/candidates/B_B_NORMAL_360_geometry.webp
python production/geometry/B_NORMAL/update_kitchen_qa.py
```

**Ограничения:** текстуры теперь действительно фотографические, но сами предметы всё ещё стилизованные низкополигональные объёмы. Ни материал, ни отражение в зеркале пока не соответствует качеству фотореалистичного референса. Перед включением в действующую игру нужны детализированные геометрия и предметы, корректное зеркало, полный оборот камеры, UV-прямоугольники хотспотов и ручное прохождение Q01/Q04. Пользовательский `game-project/project.json` и собранный HTML **не заменять** кандидатом, пока этот контроль не завершён.

Источники — CC0 по официальной лицензии Poly Haven; эти материалы можно использовать в коммерческой игре. Источник указали в документации для прозрачности. API/фотоизображения **не вызываются в runtime**.


## Этап 4 — детальная геометрия и зеркало

- **289 реальных объёмных элементов** вместо 97: отдельные обводы четырёх конфорок, кольца и ручки чайника, металлические края и слив мойки, петли шкафов, мебельные ножки, элементы холодильника, винты и планки зеркала.
- **Отражение зеркала рассчитывается вторичным лучом** с отражением обстановки рабочей кухни, а не фиксированным бирюзовым цветом. Это ограниченная трассировка одного отражения, без рекурсии и без отдельных текстур зеркала. Для будущего ужаса `B_GHOST_MIRROR` можно вводить отдельный отражающий вариант, базовая кухня остаётся нормальной.
- Семь ранее утверждённых **UV-центров Q01/Q04 не изменились**, и при каждом Actions-запуске выполняется `verify_kitchen.py`: проверка 275+ геометрических деталей, обязательных ключевых групп, результата отражённого луча, сохранности ориентиров и 2:1 текстуры.
- Панорама 2048×1024 по-прежнему имеет тот же единственный путь `art/candidates/B_B_NORMAL_360_geometry.webp`, без копий и без подмены рабочей игры. Последний тест замыкания ~3,03/255, рабочий порог 5/255.

**Художественное ограничение:** предметы стали детальнее, но ещё воспринимаются как процедурная сцена, а не как фотореалистичный интерьер. Для полного качества нужны сложные модели мебели, реалистичные источники света и ручная настройка игровых хотспотов. QA-инструмент проверяет геометрию и сохранность, не заменяет браузерную визуальную приёмку.


## Этап 5 — настоящее закругление предметов и карта взаимодействий

Круглые предметы теперь не обманка из 16 прямоугольных колец. Рендер поддерживает аналитические **эллипсоиды и цилиндры с крышками** — отдельно от прежнего списка из 289 объёмных деталей. В сцене 5 криволинейных примитивов: сферический корпус чайника, цилиндрическая крышка, кружка, тарелка и основание крана. Их столкновения лучей и нормали рассчитываются в мировых координатах и учитывают существующую фотографическую CC0-фактуру и освещение. Старые кубические формы этих предметов остаются лишь геометрическими ориентирами — при рендеринге они не рисуются. Зеркальное отражение тоже учитывает новые формы.

Добавлен генератор `production/geometry/B_NORMAL/generate_hotspots.py`, который берёт действительные ID **всех 11 действий кухни** из `game-project/project.json` и проецирует 3D-границы физических предметов в UV-панораму. Результат сохраняется в `production/qa/B_NORMAL_hotspots_candidate.json`. Из 11 действий 10 получили предварительные UV-прямоугольники: у тарелки отдельные две области по обе стороны шва 0°/360°. Событие `watch_A05` намеренно оставлено **без позиции**: в текущей модели нет авторского предмета, который надёжно обозначал бы этот эпизод. Не следует придумывать интерактивный экран на пустой стене.

**Важно:** `candidate_quads` — кандидаты 3D→UV, **не утверждённые игровые хотспоты**. Их надо проверять с полным поворотом камеры, учитывать перекрытия реальными предметами и поддержку шва в движке. `game-project/project.json` и собранные HTML-версии игры **не изменены**.

Существующая сборка GitHub Actions продолжает выпускать один файл `art/candidates/B_B_NORMAL_360_geometry.webp`, запускать прежние семь сюжетных проверок и дополнительно `verify_curved_hotspots.py`, обновлять QA-отчёт и сохранять карту кандидатов. Никаких игровых копий или отдельных веток.

Оставшаяся художественная работа: более выразительная геометрия мебели и приборов, качественное отражение зеркала в финальном рендере и ручная проверка эпизодов Q01/Q04.
